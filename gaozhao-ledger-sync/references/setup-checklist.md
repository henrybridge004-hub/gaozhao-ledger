# 首次登录与配置清单

## 1. 账号与连接器

| 项 | 要做什么 | 验收方式 |
|---|---|---|
| 钉钉 CLI | 确认 `dws` 可用；先跑 `dws version`、`dws auth status`。未登录时按 CLI 引导执行 `dws auth login`，不要把密码或验证码发到对话里 | 能列出当前用户可访问的 AI 表格 |
| 薪人薪事 MCP | 确认当前环境已安装并授权“薪人薪事”连接器；用只读招聘接口做一次小分页查询 | 能返回本人岗位或候选人列表 |
| 薪人薪事浏览器登录 | 在内置浏览器打开 `https://s.xinrenxinshi.com/staff/home`，由 HR 本人完成登录 | 能打开招聘候选人详情页 |
| 钉钉 AI 表格 | 打开/创建目标 Base，确认使用的是 AI 表格能力，不是普通共享表格 | `dws aitable base get` 能读到 Base |

薪人薪事在当前环境是 MCP 连接器，不是独立 CLI；如果其他运行环境提供同名 CLI，以该环境实际命令为准，不要凭名称猜测参数。

## 2. 首次需要收集的 ID

从钉钉 Base 和薪人薪事页面收集：

- `hr_name`：当前 HR 的显示名。
- `owner_id`：薪人薪事招聘域里的负责人 ID，用于 `jobOwners` 过滤。
- `base_id`：钉钉 AI 表格 Base ID。
- `ledger_table_id`：26 列“招聘管理/个人台账”表 ID。
- `weekly_table_id`：周度漏斗分析表 ID。
- `dashboard_id`：团队看板 ID。
- 可选：面试反馈明细表 ID、记录链接、视图 ID。

先通过 `dws aitable table get --base-id <baseId>` 回读表和字段，再把 fieldId 写入内部脚本；不要把字段名当稳定 ID 使用。

## 3. 权限与角色

- HRD Tracy、招聘运营晓欢：可查看全量个人明细、面试反馈、周度表和看板。
- 高招组 HR：只可查看本人候选人明细；公开漏斗、人数、转化率、排名可看。
- 公开漏斗和看板：不得出现姓名、手机号、最近公司、面评原文等个人明细。
- 若行级权限没有验证通过，优先使用“个人表 + 公开汇总表”，不要在一张共享表上直接赌权限。

配置后用普通 HR 账号做一次验收：打开本人表正常，打开别人的个人表被拒绝；打开公开看板能看到聚合排名。

## 4. 本地配置

1. 复制 `assets/config.example.json` 为 `config.json`。
2. 填写 HR、owner、Base/表/看板 ID 和 URL。
3. 指定 `sync_state_file`，默认 `./sync_state.json`。
4. 首次保持 `dry_run=true`。
5. 点数权重未由 HRD 确认前全部保留 0，不要自行发明。

## 5. 首次全量同步

首次没有状态文件，必须走全量模式：

1. 用显式起止日期按 `jobOwners` 分页拉候选人列表。
2. 对范围内每条 `resumeId + applyJobId` 拉取 stage-info，建立基线状态。
3. 生成 26 列台账、面试反馈、漏斗和同步报告。
4. 运行校验脚本，先让用户确认 CSV 和异常清单。
5. 确认后写入钉钉，保存每条钉钉 `recordId` 到状态文件。
6. 重算周度漏斗并检查团队看板。

只有全量基线成功后，才允许创建每日 20:30 定时任务。

## 6. 首次验收清单

- 26 列表头和顺序完全一致。
- 同一 `resumeId + applyJobId` 只有一条钉钉记录。
- 缺推荐时间、未评价、状态冲突都进入同步报告。
- 普通 HR 看不到别人明细。
- 看板只显示聚合数据，不显示候选人敏感信息。
- 状态文件已保存，且包含钉钉 recordId 映射。
