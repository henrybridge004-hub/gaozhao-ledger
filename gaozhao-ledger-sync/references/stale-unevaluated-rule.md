# 超时未评价自动转未通过规则

## 触发条件

同时满足以下条件时，把最后一个已安排面试阶段的“面试结果”从“未评价”改为“未通过”：

1. 该阶段是当前记录中最后一个有面试时间的阶段（一面、二面或三面）。
2. 该阶段“面试结果”当前精确等于“未评价”。
3. 从该阶段面试时间到执行时间已经严格超过 3 天，即超过 72 小时；等于 72 小时不触发。
4. 后续轮次没有面试时间，即没有安排后续面试。
5. 不存在已确认的 Offer、拒绝 Offer、录用审批、待入职、已入职、放弃入职等下游状态。Offer/入职只按实时单选字段的精确值判断，不做关键词包含匹配。

## 跳过条件

以下情况不自动更新，进入异常或复核清单：

- 有“未评价”状态但缺少面试时间，无法计算状态持续时长。
- 后续轮次已有面试时间，包括未来待参加的面试。
- 后续轮次已有结果、面评或面试情况，说明数据已经推进或存在轮次不一致。
- 已有 Offer、录用审批、待入职、已入职等积极下游状态。
- 最后一轮面试时间尚未发生。
- 未评价时长未满或刚好等于 3 天。
- 任一已排期轮次的过程、面评、结果或原因中出现“取消/cancel”，说明可能存在取消或改期，转人工复核。
- 面试时间和执行时间必须包含明确时区；无时区、非法时间或非法 singleSelect 选项直接跳过并记录错误。

“无”“未发offer”“未入职”等默认值不视为积极下游状态；“拒绝offer”“放弃入职”说明已经进入下游流程，同样不改写前面的面试结果。

## 写入边界

- 只更新对应轮次的面试结果字段：
  - 一面：`mwv1H5x`
  - 二面：`7NfUhqb`
  - 三面：`6n4KvRS`
- 目标值固定为“未通过”。
- 不自动填写该轮原因、面评或面试情况。
- 不改写更早轮次的“未评价”；如果二面已被判定为未通过，一面仍可能保留历史“未评价”状态。
- 字段级人工锁定落地前，必须先 dry-run，并在回读时检查是否存在外部或人工变更。
- 当前表没有真实“状态变更时间”字段，72 小时以面试时间为代理；改期、补录或状态历史不明的记录必须人工复核，不能把它解释为严格的状态持续时长。

## 执行流程

```powershell
python scripts/apply_stale_unevaluated_rule.py `
  --records ./records.json `
  --table-json ./fields.json `
  --out-updates ./stale_unevaluated_updates.json `
  --out-report ./stale_unevaluated_report.json
```

然后使用钉钉 CLI 对 `stale_unevaluated_updates.json` 先执行 record update dry-run，确认后正式写入；写入后再次回读并复核，确认符合条件的记录数为 0。
