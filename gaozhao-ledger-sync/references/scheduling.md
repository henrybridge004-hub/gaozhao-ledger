# 每日定时同步

## 推荐节奏

- 每日一次，默认 `20:30`（按团队下班后的时间改，避开白天高峰期）。
- 先做 30 天滚动增量，再做一次全量周校验。
- 周一可额外跑一次“周漏斗”，生成上周汇总和排名。

## 增量窗口

不要只查“昨天”。招聘流程推进可能发生在投递后很久，只查昨天会漏掉：

- 推荐：`applyTime` 昨天
- 业务复筛：投递后几天才反馈
- 面试：推荐后 1–2 周
- offer/入职：面试后 1–4 周

默认配置：

```json
{
  "date_window": {
    "mode": "rolling_days",
    "days": 30
  }
}
```

首次回填用 `mode: "explicit"`，写明起止日期。每次同步按 `resumeId + applyJobId` upsert，不会因为滚动窗口重复追加。每日列表仍需滚动拉取，但 stage-info 详情只对新增或变化记录抓取，具体状态文件和去重规则见 `sync-state.md`。

## 定时任务模板

用当前环境的 `create_cron_job`，不要只回复“我会每天跑”。

- `title`: `高招台账每日同步`
- `schedule_type`: `cron`
- `schedule`: `30 20 * * *`（按 `config.daily_run_time` 改）
- `runtime_type`: `1`（云端）优先；只有必须读本地文件/本地登录态才用 `2`
- `enable`: `true`
- `query` 示例：

```text
本次请求是由「高招台账每日同步」定时任务到时触发的。
读取 <config.json 绝对路径>，执行高招台账增量同步：
1. 用薪人薪事 getResumeList 按 jobOwners + 最近 30 天 applyTime 拉候选人；
2. 用浏览器同步 XHR 拉 stage-info；
3. 运行 scripts/build_ledger.py 和 scripts/validate_ledger.py；
4. 按 resumeId + applyJobId 更新钉钉个人台账、面试反馈明细和公开漏斗；
5. 只汇报新增/更新/异常，不展示候选人明细；
6. 登录态失效时停止，不写入旧数据。
```

## 登录态

- 薪人薪事 MCP 依赖连接器授权；浏览器 stage-info 依赖 `s.xinrenxinshi.com` 登录态。
- 云端定时任务不能假设本地浏览器 Cookie 一定可用；优先用连接器或可复用登录态。
- 登录失效时：
  1. 停止写入；
  2. 提示用户重新登录；
  3. 不要用上一次缓存冒充当天数据；
  4. 不要反复重试同一失败请求。

## 幂等与失败处理

- 每次运行生成 `sync_report.json`，记录 `run_id`、时间窗、拉取数、新增、更新、跳过、异常。
- 钉钉写入失败时，保留本地 CSV 和报告；下次运行先读钉钉表现有键，再补写。
- 同一 `resumeId + applyJobId` 不会重复追加。
- 如果公开漏斗写入失败，个人台账可以保留；但必须在报告里标红“漏斗未更新”。

## 通知

- 成功：只发一条聚合摘要（新增/更新/面试/异常数）。
- 失败：发失败原因和需要用户做的事（重新登录/恢复表头/人工确认状态冲突）。
- 不在群里发候选人姓名、手机号、面评原文。
